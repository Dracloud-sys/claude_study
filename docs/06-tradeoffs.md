# 06. 장단점 종합 비교

각 문서에 흩어진 트레이드오프를 한곳에 모았다. **"무엇을 포기하는가"** 기준으로 읽을 것.

---

## A. 모델 선택

| 선택지 | 장점 | 단점 | 언제 |
|---|---|---|---|
| 프론티어 최상위 (Opus 5급) | 멀티스텝 에이전트 성공률 최고, 재시도 적어 **총비용이 오히려 쌀 수 있음** | 토큰 단가 최고, 응답 느림 | 설계, 어려운 디버깅, 장기 자율 작업 |
| 중소형 (Haiku/Flash급) | 저렴·빠름, 대량 처리 | 긴 추론·도구 연쇄에서 이탈 | 분류·요약·변환 반복 |
| 오픈웨이트 자체호스팅 | 토큰 과금 0, 데이터 미유출, 무제한 반복 | GPU 비용·운영 부담, 에이전트 성능 열세 | 민감 데이터, 대량 배치 |
| 로컬 소형(노트북) | 오프라인, 지연 낮음, 완전 프라이빗 | 성능 격차 큼, 하드웨어 상한 | 실험, 전처리, 마스킹 |
| 멀티벤더 병행 | 벤더 락인 회피, 장애 대비, 작업별 최적 | 프롬프트·평가 이중 관리, 복잡도 | 팀/제품 규모 |

**공통 함정**: 벤치마크 순위로 고르기. → 자체 eval 10건으로 결정할 것.

## B. 사용 기법

| 기법 | 장점 | 단점 |
|---|---|---|
| CLAUDE.md에 규칙 내리기 | 매 실행 자동 적용, 팀 공유, 버전관리 | 길어지면 매 실행 비용·노이즈. 관리 안 하면 낡음 |
| 스킬(SKILL.md) 자산화 | 재사용·리뷰·개선 가능, 결과 일관성 | 초기 작성 비용, 개수 늘면 오발동 |
| 서브에이전트 | 메인 컨텍스트 보호, 병렬 조사 | 토큰 증가, 결과 통합 손실, 남발 시 느려짐 |
| MCP 커넥터 다수 연결 | 외부 시스템 실작업 가능 | 도구 스키마가 컨텍스트 잠식, 오호출, **보안 표면 확대** |
| Plan → Execute 분리 | 큰 작업 통제, 비용 예측 가능 | 단계가 늘어 총 소요시간 증가 |
| RAG | 코드 밖 지식 활용 | 파이프라인 유지보수, 검색 실패가 조용한 오답으로 |
| 자체 eval | 개선을 **측정**할 수 있음. 유일한 객관 근거 | 구축·유지 비용, 정답 만들기 어려움 |
| 컨텍스트 압축(`/compact`) | 긴 세션 지속 | 손실 발생. 결정사항은 파일로 남겨야 |

## C. 프로젝트 관리 방식

| 방식 | 장점 | 단점 |
|---|---|---|
| AI 산출물 = 항상 PR | 되돌리기 쉬움, 감사 추적, 리뷰 자연스러움 | PR 폭증 시 리뷰 병목 |
| AI 자동 리뷰 도입 | 기계적 지적을 사람 앞에서 걷어냄 | 오탐 많으면 전부 무시하게 됨(신뢰 붕괴) |
| 사람 머지 필수 유지 | 안전, 책임 소재 명확 | 속도 상한이 사람에 걸림 |
| 자동 머지 허용 | 처리량 최대 | 사고 시 복구 비용이 절감분을 초과하기 쉬움 — **권장 안 함** |
| 읽기전용부터 단계 도입 | 신뢰 축적, 실패 비용 낮음 | 성과 체감까지 시간 |
| 처음부터 전면 자동화 | 빠른 도입감 | 규칙 미정착 상태라 산출물 품질 낮고 신뢰 상실 |

## D. 클라우드 ↔ 로컬 병행 (2번 질문)

| 방식 | 장점 | 단점 | 적합 |
|---|---|---|---|
| **A. 세션 왕복** (`--cloud` / `--teleport`) | 로컬 자원 무소모, 닫아도 진행, 병렬 확장, 모바일 조종 | GitHub 의존, 로컬 파일·사내망 접근 불가, 사용량 한도 공유 | **기본값** |
| **B. GitHub 허브** (`@claude`, Actions, Auto-fix) | 결과가 PR 한 곳에 수렴, 팀 공용 인터페이스, 감사 추적 | GitHub 전제, Actions분+토큰 이중과금, 권한 설계 필요 | 팀 협업 |
| **C. 로컬+원격조종** (`--remote-control`) | 로컬 파일/사내망 그대로, 어디서나 개입 | PC 켜져 있어야, 로컬 자원 점유 | 로컬 의존 작업 |
| **D. 로컬 오픈웨이트** | 데이터 미유출, 과금 0, 오프라인 | 성능 열세, 하드웨어·운영 부담 | 민감 데이터 전처리 |

## F. 전체를 관통하는 3가지 트레이드오프

1. **자율성 ↔ 통제**
   자율성을 올리면 처리량이 오르고 사고 비용도 오른다.
   → 해법: *되돌리기 쉬운 영역(브랜치/PR/초안)에서만 자율성을 최대화*하고, 되돌리기 어려운 지점에 사람 게이트를 둔다.

2. **속도 ↔ 검증**
   AI는 코드를 쓰는 속도를 10배로 만들지만 **리뷰 속도는 안 올려준다.** 리뷰가 병목이 되면 전체 처리량은 그대로다.
   → 해법: 기계 검증(CI)과 AI 리뷰로 사람 리뷰 대상을 줄인다. PR을 작게 쪼갠다.

3. **편의 ↔ 보안**
   커넥터·권한·네트워크를 열수록 할 수 있는 일이 늘고 프롬프트 인젝션 표면도 넓어진다.
   → 해법: 작업별 최소 권한. 자동화 루틴일수록 더 좁게. 외부 콘텐츠는 항상 신뢰 불가로 취급.
